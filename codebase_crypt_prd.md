Problem Statement & VisionThe ProblemEvery growing software repository accumulates invisible decay: orphaned files nobody imports, high-churn modules that break on every sprint, and forgotten TODO/FIXME comments from months ago. Existing static analysis tools report these issues as dense spreadsheets or long terminal logs that developers routinely ignore—and even when a developer spots a problem, translating a warning into a safe refactoring plan still takes manual effort.The VisionCodebase Crypt turns any public GitHub repository into an interactive, gothic haunted crypt where spooky visual metaphors communicate real engineering health at a glance:Ghosts reveal dead or orphaned code.Cursed Relics highlight high-churn, overly complex technical debt.Tombstones mark stale modules and unresolved TODO/FIXME debt.Instead of stopping at diagnosis, clicking Exorcise on any haunted module generates a ready-to-run .kiro refactoring spec (requirements.md, design.md, tasks.md), closing the loop from visual triage to AI-assisted cleanup.2. Core User JourneysJourney 1: First-Time Visitor -> Instant DemoUser lands on / and sees a dark gothic hero with a GitHub URL input and three Instant Demo Crypts cards.User clicks a demo card (e.g., a recognizable OSS repo).The Crypt Explorer (/crypt/[owner]/[repo]) opens immediately from pre-cached fixtures with the overall Haunting Grade (Sanctified, Restless, Haunted, or Cursed) and animated crypt nodes.Journey 2: Live Public GitHub Repo SummoningUser pastes https://github.com/owner/repo and clicks Summon Crypt.An atmospheric scanning loader shows progress ("Unearthing file tree...", "Reading commit spirits...", "Calculating curses...").The app renders the interactive Crypt Map grouped by directory chambers, with an explicit notice if a large repo was capped at the top 120 source files.Journey 3: Visual Triage & InspectionUser clicks filter pills in the top HUD (All, Ghosts, Cursed Relics, Tombstones) or searches by filename.Non-matching nodes dim smoothly while matching haunted nodes stay illuminated.User clicks any node to open the Inspector Drawer, showing its Haunting Score (0–100), plain-English reasons for the classification, raw metrics (LOC, Commits, Age, TODOs, Inbound Refs), and a direct GitHub file link.Journey 4: One-Click "Exorcise" -> .kiro Spec BundleInside the Inspector Drawer for any haunted file, user clicks Exorcise with Kiro Spec.The Exorcise Modal displays a brief summoning state, then renders three tabbed Markdown files: requirements.md (EARS format), design.md, and tasks.md.User copies individual files or clicks Download .kiro Spec ZIP to get a folder ready to drop into .kiro/specs/exorcise-<slug>/.Journey 5: Graceful Error & Rate-Limit HandlingIf a user enters a private repo, typo, or hits GitHub API rate limits, the UI displays a clear, themed error card explaining why and offering a one-click button to open an Instant Demo Crypt instead.5. Costume Contest UX & Design PrinciplesSpooky = Informative: Never add Halloween clutter that obscures text or file paths. Every animation must signify state (floating = orphaned ghost; warm orange pulse = high-churn hotspot; amber badge = stale TODOs).Dark-Mode Legibility First: Bone-white primary text (#F4F1EA) on obsidian/stone surfaces (#0B0A10 / #151320) with monospace file paths (JetBrains Mono) so judges can read every label effortlessly in a 1080p demo video.Zero Dead Ends: Every screen has a clear next action—Landing -> Summon or Demo; Crypt Map -> Filter or Inspect; Inspector -> Exorcise; Exorcise Modal -> Copy or Download .kiro ZIP.7.
